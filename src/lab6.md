# ЛР 6. Трассировка и логирование

Стенд запускает API из ветки тестирования, PostgreSQL и Neo4j с APOC. OpenTelemetry собирает HTTP-спаны, операции Npgsql и спан `cascading-failure`. Tempo принимает трассы по OTLP. В Grafana доступны Tempo и Prometheus, а Seq получает журналы Serilog.

## Локальный запуск

Из `src` с Docker Compose, Python 3 и k6 выполните `make lab6`. Команда поднимает стенд, создаёт тестовый граф из 10 компонентов и 9 связей и запускает четыре режима по 10 минут с 1500 виртуальными пользователями. Для подготовки администратор входит один раз. Нагрузочный пользователь входит один раз, и его JWT используется во всех четырёх режимах и при прогреве. Каждый VU в цикле читает системы, читает компоненты и запускает анализ каскадного сбоя с нулевой долей искусственных ошибок.

Результаты появляются в `results/lab6`. Для повторного запуска укажите новую папку, например `make lab6 LAB6_OUTPUT=results/lab6-repeat`. Для изменения длительности задайте `SOAK_DURATION=2m`, а для изменения числа пользователей задайте `SOAK_VUS`. При повторном запуске с готовым образом можно передать `--no-build` скрипту `scripts/run-lab6.py`.

| Режим | `Observability__TracingEnabled` | `Observability__VerboseLogging` |
|---|---|---|
| baseline | false | false |
| tracing | true | false |
| verbose | false | true |
| tracing-verbose | true | true |

В расширенном режиме Serilog принимает события уровня Debug и выше. Источники ASP.NET Core и EF Core настроены на Information. Контейнеры мониторинга запущены во всех режимах, поэтому в отчёте видны расходы самих сервисов и изменения их потребления при включении трассировки и расширенного логирования. Для каждой пары режимов отчёт показывает разницу CPU на 1000 запросов и средней памяти API.

Grafana доступна по адресу `http://127.0.0.1:3006`. Откройте Explore, выберите Tempo и найдите трассу по идентификатору из отчёта. API Tempo также доступен на `http://127.0.0.1:3200`. После замеров стенд можно остановить командой `docker compose -f docker-compose.lab6.yml stop`.

## GitHub Actions

Workflow `Lab 6 / Observability` запускает ту же матрицу на push в `testing_06`, на pull request с релевантными изменениями и вручную через `workflow_dispatch`. Шаг запуска проверяет трассу запроса k6 в каждом режиме. При включённой трассировке он сохраняет HTTP-спан и вложенный спан анализа из Tempo. При выключенной трассировке он проверяет ответ HTTP 404 по идентификатору. Отчёт, снимки ресурсов, метрики k6 и JSON трасс доступны в артефакте `lab6-soak0`.
